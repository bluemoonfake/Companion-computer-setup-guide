# 05 — RM520N-GL 5G (CDC-ECM)

Use Ubuntu 24.04, NetworkManager, a compatible USB 3.0 adapter, data SIM and antennas. Power off before changing SIM/antennas; perform network changes from a local console.

## Recommended: interactive setup

From the repository root:

~~~bash
sudo ./config --check
sudo ./config
sudo ctuav-net status
sudo ctuav-net logs
~~~

Choose ECM only or ECM + Wi-Fi. Reuse a saved Station profile, set the Hotspot password and enable the watchdog. Do not run legacy reset/Hotspot services.

## 1. Detect modem

~~~bash
sudo apt install -y network-manager minicom usbutils iputils-ping python3-serial
lsusb -d 2c7c:0801
lsusb -t
ls -l /dev/ttyUSB*
nmcli device status
~~~

Expected USB ID 2c7c:0801; ECM driver cdc_ether. If already connected, skip manual AT changes.

## 2. AT port (manual recovery only)

If ModemManager owns the port, stop it only on a dedicated ECM host with no other modem dependencies.

~~~bash
sudo systemctl stop ModemManager.service
sudo minicom -D /dev/ttyUSB2 -b 115200
~~~

Verify the actual AT port first. Enter these commands inside minicom, not Bash.

~~~text
AT
ATI
AT+CPIN?
AT+CEREG?
AT+QCFG="usbnet"
AT+QCFG="data_interface"
AT+CGDCONT?
AT+QNWPREFCFG="mode_pref"
AT+QNWPREFCFG="nr5g_disable_mode"
AT+QMAPWAC?
~~~

Expect ATI identifying RM520N and SIM READY. On dedicated ECM installations only, ModemManager may be disabled if it conflicts.

## 3. Enable ECM (only if missing)

Replace YOUR_APN with the operator's data APN. Check OK after each command; stop if the firmware rejects one.

~~~text
AT+QCFG="usbnet",1
AT+QCFG="data_interface",0,0
AT+CGDCONT=1,"IPV4V6","YOUR_APN"
AT+QNWPREFCFG="mode_pref",AUTO
AT+COPS=0
AT+QMAPWAC=1
AT+CFUN=1
AT+CFUN=1,1
~~~

Reset disconnects the modem; exit minicom (Ctrl+A then X), wait for USB re-enumeration and verify settings. If NR was disabled, use supported nr5g_disable_mode setting 0 only after checking the firmware.

## 4. Manual NetworkManager profile (alternative to config)

Use only with one cdc_ether modem; do not bind to a changing MAC/interface name.

~~~bash
if ! nmcli connection show CTUAV_cc_5G >/dev/null 2>&1; then
  sudo nmcli connection add type ethernet ifname '*' con-name CTUAV_cc_5G
fi
sudo nmcli connection modify CTUAV_cc_5G \
  connection.interface-name '' 802-3-ethernet.mac-address '' \
  match.driver cdc_ether connection.autoconnect yes \
  connection.autoconnect-priority 100 connection.autoconnect-retries 0 \
  ipv4.method auto ipv4.route-metric 100 \
  ipv6.method auto ipv6.route-metric 100
sudo nmcli -w 60 connection up CTUAV_cc_5G
~~~

If profiles compete, disable autoconnect only on the identified conflicting ECM profile.

## 5. Verify Internet

~~~bash
nmcli device status
ip -4 route
ip route get 1.1.1.1
ping -c 10 1.1.1.1
~~~

Expect DHCP and default route via ECM (metric 100). Reboot and unplug/replug the USB modem from a local console; verify reconnection.

## 6. Read RF status (optional)

Open the verified AT port in minicom as above; close minicom before running RF monitoring.

~~~text
AT+QENG="servingcell"
AT+QNWINFO
AT+QCSQ
AT+CGPADDR
AT+QNWPREFCFG="nr5g_disable_mode"
~~~

## 12. USB Wi-Fi / Hotspot

The installer manages both profiles; modem present → AP, absent → Station (fallback AP if unavailable). This is USB presence switching, not Internet health failover.

| Profile | Setting |
|---|---|
| CTUAV_Hotspot | SSID CTUAV_cc_5G, 192.168.50.1/24, shared IPv4 |
| Station | Saved Wi-Fi profile, DHCP, metric 600 |
| Both Wi-Fi profiles | Autoconnect off; watchdog selects mode |

### 12.2. Check AP support

~~~bash
sudo apt install -y dnsmasq-base iw avahi-daemon
sudo systemctl enable --now avahi-daemon
iw dev
read -r -p 'USB Wi-Fi interface: ' WIFI_IF
nmcli -f WIFI-PROPERTIES.AP device show "$WIFI_IF"
readlink -f "/sys/class/net/$WIFI_IF/device/driver"
~~~

If AP fails with missing dnsmasq, install dnsmasq-base and restart the watchdog; do not install a competing standalone DNS service.

~~~bash
sudo apt install -y dnsmasq-base
sudo systemctl restart ctuav-network.service
sudo journalctl -u NetworkManager -b -n 80 --no-pager
~~~

### Optional RTL8822BU driver fix

Only for the tested Orange Pi 6 image, USB ID 2357:0138, with persistent Wi-Fi instability. Confirm the installed alternate module supports the device/kernel and both options; keep a local console.

~~~bash
uname -r
modinfo -F alias 88x2bu | grep -i v2357p0138
modinfo -F vermagic 88x2bu
modinfo -p 88x2bu | grep -E 'rtw_power_mgnt|rtw_ips_mode'
~~~

If all checks match, create the override and reboot; otherwise keep the current driver.

~~~bash
sudo tee /etc/modprobe.d/99-ctuav-wifi.conf >/dev/null <<'CONF'
blacklist rtw88_8822bu
options 88x2bu rtw_power_mgnt=0 rtw_ips_mode=0
CONF
sudo reboot
~~~

To revert, remove only this override file and reboot.

### Verify switching

~~~bash
sudo journalctl -fu ctuav-network.service
~~~

Unplug/replug only the modem USB cable; expect Station/AP transitions. From a Hotspot client, ping 192.168.50.1 and test SSH.

### Recovery

From local console, stop the watchdog and activate the saved Station profile. Replace UUID with the actual Station UUID.

~~~bash
sudo systemctl stop ctuav-network.service
nmcli connection show
sudo nmcli con mod uuid UUID connection.autoconnect yes
sudo nmcli con up uuid UUID
~~~

To resume automatic switching, restore Station autoconnect to no and restart the service.

~~~bash
sudo nmcli con mod uuid UUID connection.autoconnect no
sudo systemctl enable --now ctuav-network.service
~~~

Root-only backups: /var/backups/ctuav-network. No automatic rollback of modem settings. See [quality tests](NETWORK_QUALITY.md).
