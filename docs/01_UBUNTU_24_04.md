# 01 — Ubuntu 24.04 companion computer

## Platform and installation

Use Ubuntu 24.04 LTS (Noble), 64-bit ARM64 on Raspberry Pi 5 or Orange Pi 6, or amd64 on a compatible PC. The Pi 5 uses the Raspberry Pi-compatible Ubuntu image; Orange Pi 6 requires its board-specific Noble image/boot firmware. Do not flash a Raspberry Pi image to Orange Pi or install a generic kernel over a vendor BSP without verifying support. The RM520N installer was exercised on Orange Pi 6, kernel 6.6.89-cix; Pixhawk Ethernet was exercised on Raspberry Pi 5. This is not a claim that every board/driver combination is validated.

- Use a reliable power supply, cooling and adequate storage. Prefer an SSD for logs/builds where supported. Back up before flashing; flashing erases the selected device.
- For Pi 5 choose the correct Ubuntu image from [Ubuntu for Raspberry Pi](https://ubuntu.com/download/raspberry-pi) or Raspberry Pi Imager. For Orange Pi 6 use its vendor image and matching board documentation.
- Set an initial admin user, strong password and local access. Keep a display/keyboard or other independent recovery link during network changes.

~~~bash
cat /etc/os-release
uname -a
dpkg --print-architecture
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS
df -h /
free -h
timedatectl
~~~

Confirm Noble, correct board kernel and free space. Before upgrading, review the package transaction, especially vendor kernel and bootloader packages. Never blindly replace the board kernel.

~~~bash
sudo apt update
sudo apt upgrade
sudo apt install -y git curl ca-certificates jq build-essential cmake ninja-build pkg-config \
  python3 python3-pip python3-venv python3-setuptools python3-numpy \
  python3-serial usbutils pciutils iproute2 iputils-ping ethtool tcpdump \
  minicom psmisc openssh-server avahi-daemon avahi-utils locales
sudo locale-gen en_US.UTF-8
sudo update-locale LANG=en_US.UTF-8
~~~

Optional application libraries (not required by MAVLink/DDS):

~~~bash
sudo apt install -y python3-opencv python3-paho-mqtt
~~~

Use a virtual environment for additional pip packages rather than overriding Ubuntu's externally managed system Python. Use apt for ROS packages.

## Identity, SSH and mDNS

Example identity: user ctuav, hostname orangepi (or a unique hostname for each board). Do not create a duplicate account or delete the original user before checking service dependencies. If the desired account exists, use sudo passwd ctuav; otherwise:

~~~bash
sudo adduser ctuav
sudo usermod -aG sudo,dialout ctuav
sudo hostnamectl set-hostname orangepi
sudoedit /etc/hosts
~~~

Update an existing 127.0.1.1 hostname line to match the new hostname; keep localhost entries. Log in as the new user and verify id and sudo whoami. If using SSH keys, install your public key for that account using ssh-copy-id from a trusted client and verify login before changing SSH authentication policy.

~~~bash
sudo systemctl enable --now ssh avahi-daemon
systemctl is-active ssh avahi-daemon
hostnamectl
~~~

From a client on the same LAN:

~~~bash
ssh ctuav@orangepi.local
~~~

Use the actual hostname/username. mDNS .local works on a suitable local link, not automatically across the VPN. Do not publish keys, credentials, MACs or private fleet identifiers. If UFW is active, permit SSH only from intended management networks; do not open all ports globally or enable a firewall remotely without preserving access.

## NetworkManager and clock

~~~bash
systemctl is-active NetworkManager
nmcli device status
ip -br address
ip -4 route
ls -l /etc/netplan
timedatectl status
~~~

The RM520N config and Wi-Fi watchdog require NetworkManager. The PX4 Ethernet examples also use it. On an image using systemd-networkd, install network-manager and deliberately migrate only the intended interfaces using Netplan from the console. Back up /etc/netplan and existing NetworkManager profiles first; do not run conflicting renderers on the same link. No global renderer change is necessary on images already using NetworkManager.

Keep system clock synchronized through the available time-sync service (systemd-timesyncd or chrony). PX4 DDS timestamp synchronization is separate from OS NTP. Check CPU temperature, USB enumeration and disk space before long builds.
